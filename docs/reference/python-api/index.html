Python API

Use this page to find which MVIS module to import for each job. MVIS is a Python library: the mvis command is a thin layer over the functions below. The package is pymvis; you import it as mvis.

A map, not generated docs

We wrote this page by hand from the MVIS 0.1.0 source. The docstrings in the repository hold the full signatures. MVIS 0.x releases may change the Python API and the config schema; the changelog lists what changed.

Package layout

Section titled “Package layout”
ModuleContents
mvis.coreResult types (Observation, CameraParams, CalibrationResult), the config dataclasses, timing
mvis.cameraOne CameraModel class per camera model: projection, Jacobians and unprojection in one place
mvis.detectionBoards (chessboard, AprilGrid, ArUco), detectors, frame quality, corner subsampling
mvis.ioData sources, the streaming detection pipeline, image decoding, the camera–IMU loader, output writers, Kalibr and Basalt files
mvis.imuIMU intrinsic models (kalibr, rpng, calyx), resampling, Allan-variance analysis
mvis.calibrationFirst guess, factor graph, camera-only and camera–IMU pipelines, outlier rejection
mvis.simulationSynthetic camera–IMU data, digital twins, simulator examples
mvis.recalibapply-calib and roundtrip
mvis.datasetsThe dataset catalog behind mvis datasets
mvis.doctormvis check and mvis inspect
mvis.mvisdbThe capture database
mvis.analysisHTML reports, plots, the Rerun 3D view, motion analysis, verdict
mvis.cliThe mvis command

Terms:

  • Jacobian: the derivatives of a projection with respect to its inputs; the solver needs them.
  • Unprojection: the reverse of projection, from a pixel back to a viewing ray.
  • First guess: OpenCV’s pose-from-known-points solve (PnP) and a focal-length estimate, before the joint solve.

Kalibr files

Section titled “Kalibr files”

mvis.io.kalibr is the one place for Kalibr files.

FunctionDoes
read_camchain(doc)A Kalibr camchain dict → per-camera intrinsics, distortion, resolution
read_camchain_imucam(doc)Also each camera’s T_cam_imu and the stereo T_cn_cnm1
write_camchain_imucam(result)A camera–IMU result → a camchain-imucam dict, ready for yaml.safe_dump
parse_results(path), camera_only(dir), camera_imu(dir)Read the output files of a finished Kalibr run

A camchain is Kalibr’s YAML file of camera parameters. T_cam_imu maps points from the IMU frame into the camera frame. T_cn_cnm1 maps points from the previous camera into this one.

Kalibr AprilGrid target files load with mvis.detection.apriltag_board.AprilTagBoard.from_kalibr_yaml(path). Any board: config block builds a board with mvis.detection.board_factory.create_board(BoardConfig).

Camera and IMU models

Section titled “Camera and IMU models”
  • mvis.camera: PinholeRadtan, PinholeEquidistant, KannalaBrandt4, FOVModel, DoubleSphere, EUCM, UCM, OmniRadtan. Each projects, unprojects and gives Jacobians.
  • mvis.imu: the three IMU intrinsic models and their correction matrices (dw_matrix, da_matrix, tg_matrix). See IMU model.

Simulation

Section titled “Simulation”

Simulator examples: a real recorded motion with a full rig setup, ready to simulate.

The installed package ships twin_gs. A source checkout also has the others under data/sim_examples/, led by virig_4imus_3cams. Their true values are real solves moved by a fixed, seeded perturbation, so no real device calibration ships.

Digital twins of whole recordings are in mvis.simulation.twin: capture(config_path, name) builds a twin from a config and its recording, Twin.load(path) reads a saved one, and solve(twin) simulates, runs the real solver and returns the errors against the truth. See Digital-twin check.

Reports

Section titled “Reports”

board and reference are optional; without board the report has no board in the 3D scene. To rebuild a camera-only report from a finished run folder: python -m mvis.analysis.regenerate_html <run folder> --config <config>.

Why the models live in one place

Section titled “Why the models live in one place”

A report cannot disagree with the fit it describes: it computes residuals with the same code the solver minimised.

  • mvis.camera holds each model’s projection, Jacobian and unprojection together.
  • mvis.calibration.factors.camera_projection is shared by the solver and the HTML report.
