## MVIS 0.4.1

Released on 2026-11-25 ([PyPI](https://pypi.org/project/pymvis/0.4.1/),
[Zenodo](https://doi.org/10.5281/zenodo.24541924)). The same config gives the
same solve as on 0.4.0.

- **The report names the place:** a comment after the gravity value,
  `gravity: 9.8013   # m/s², Newark, Delaware`, gives "set in config for Newark,
  Delaware" in the camera–IMU report, `cam_imu.json` (`gravity_place`) and
  `mvis check`. With `site:` the site name is used, as before.
- **Configs set the local gravity first:** the example configs, the run-log hint
  and the agent template now start with the local `gravity:` value. Results
  published from the old example configs were solved at 9.81, so their
  accelerometer scale differs by 0.02–0.17 % from a re-solve.

## MVIS 0.4.0

Released on 2026-11-24 ([PyPI](https://pypi.org/project/pymvis/0.4.0/),
[Zenodo](https://doi.org/10.5281/zenodo.24522452)). A config that ran on 0.3.0
runs unchanged: without `gravity:` or `site:` the solve keeps 9.81.

- **Local gravity:** `gravity:` (m/s²) or `site: {latitude_deg, altitude_m}`
  sets the gravity of a camera–IMU solve. The accelerometer scale absorbs a
  wrong value, so a fixed 9.81 read it 0.23 % high in Shenzhen and up to 0.30 %
  at the equator. The value used, and its site, are in the results, the
  calibration YAML and the report; without either key the run log warns that
  9.81 is in use. See [Local gravity](/reference/local-gravity/).
- **Start checks:** board and multi-camera camera–IMU runs report failed start
  checks (gravity norm, scale) as a warning, a report line and an `init_gates`
  block in `cam_imu.json`.
- **Fixed:** gyro-only auxiliary IMUs applied their time offset twice (a 50 ms
  offset came out as 0.35 ms). The report's bias values are labelled as the first
  state's, and the bias plot shows the biases per state.

## MVIS 0.3.0

Released on 2026-11-22 ([PyPI](https://pypi.org/project/pymvis/0.3.0/),
[Zenodo](https://doi.org/10.5281/zenodo.24444718)). A config that ran on 0.2.0
runs unchanged.

- **ChArUco boards** (`board_type: charuco`): chessboard corners named by ArUco
  markers, so a board that is partly out of view is still used. `rows` and
  `cols` count squares, and the dictionary is required. MVIS refines each corner
  after OpenCV, whose corners sit about 0.5 px off. Needs OpenCV 4.7 or later.
  Keys: [Configuration](/reference/configuration/#board).

## MVIS 0.2.0

Released on 2026-11-19 ([PyPI](https://pypi.org/project/pymvis/0.2.0/),
[Zenodo](https://doi.org/10.5281/zenodo.24385919)). Results files gain fields;
nothing is removed or renamed.

- **ROS2 bags without ROS:** a bag folder, or one `.db3` or `.mcap` file, in both
  modes, read with `rosbags`.
- **Reprojection statistics:** mean, median, standard deviation, P90, P95 and
  max per camera and overall, also for the corners within 3 px.
- **Reports redesigned:** a Summary with the parameters per sensor, camera tabs,
  a closed Appendix, a print view, and IMU residuals per state block. Reports
  name the installed version.
- **Fixed:** a camera-only solve that stops stuck is solved again from its start
  with other damping, and `mvis verdict` grades it RED if it is still stuck.

## MVIS 0.1.0

The first public release. There is no earlier public version, so the list
describes the toolbox as it ships. Released on 2026-11-15, on
[PyPI](https://pypi.org/p/pymvis) and [Zenodo](https://doi.org/10.5281/zenodo.24239182).

- **Package:** `pymvis` (import and command `mvis`), Linux and macOS (Windows
  tentative), Python 3.11 and 3.12.

### Calibration

- **Camera-only** (`mvis cam`): one or more cameras; intrinsics, distortion,
  extrinsics, camera–camera time offset and rolling-shutter readout (the time
  the sensor takes to read the image row by row).
- **Camera–IMU** (`mvis cam-imu`): camera–IMU extrinsics, time offset `td`,
  readout, camera intrinsics, IMU intrinsics, biases, the gyro–accel offset
  `t_ga` (for the base IMU and every auxiliary IMU that is not `gyro_only`),
  and the extrinsics and time offsets of further IMUs.
- **Camera models:** eight, usable in both modes and mixed within one rig:
  `radtan`, `equidistant`, `kb4`, `fov`, `double_sphere`, `eucm`, `ucm` and
  `omni_radtan` (experimental). `fisheye` means `kb4`.
- **IMU conventions:** `kalibr`, `rpng` and `calyx`, with scale and
  misalignment (`Dw`, `Da`) and optional g-sensitivity (`Tg`).
- **`estimate:` block:** chooses what is solved and what is held, including the
  board shape (`board_points`).
- **One command for both modes:** `mvis run` runs either mode from one config
  (`mode: cam` or `mode: cam-imu`).
- **Batch:** `input.bags` calibrates a whole set of recordings from one config.

### Input and output

- **Inputs:** image folders, timestamped images, ROS1 bags (`Image`, and PNG or
  JPEG `CompressedImage`), ROS2 bags and EuRoC / ASL folders.
- **ROS2 without ROS:** ROS2 bags (a bag folder, or one `.db3` or `.mcap` file)
  are read with the pure-Python `rosbags`, with no ROS install.
- **Boards:** AprilGrid, chessboard and ArUco (ChArUco since 0.3.0).
- **Kalibr interop:** read and write Kalibr camchains.
- **Output:** YAML calibration files, JSON results and self-contained HTML
  reports for both modes.
- **Datasets:** `mvis datasets` lists, downloads and verifies the Calibench-VI
  datasets on Hugging Face.

### Tools

- **`mvis apply-calib`:** writes a corrected copy of a ROS1 bag: IMU intrinsics
  and bias removed, streams re-stamped by `td`, accelerometer shifted by `t_ga`,
  images optionally undistorted.
- **`mvis roundtrip`:** calibrates, applies the result, calibrates again, and
  gives a PASS/FAIL report. ROS1 bags only.
- **`mvis check`, `mvis inspect`, `mvis verdict`:** check the environment and
  config, summarise a dataset, and grade a finished result.
- **Simulator** (`mvis.simulation`): digital twins of real recordings.

## Datasets

The datasets are on
[Hugging Face](https://huggingface.co/datasets/calibench-vi/datasets). Each set
and its licence is listed on [Datasets](/datasets/).

- **VI-Rig recordings (ours):** multi-camera, multi-IMU recordings, CC BY 4.0
  and gated.
- **Partner recordings:** Looper and GiLabs, on the same terms.
- **Converted third-party sets:** Monado MIC, MGC and MOC, and the TUM-VIE frame
  cameras, CC BY 4.0.

### Main repository open to commercial use (2026-11-25)

- **Now CC BY 4.0, commercial use included:** every recording in
  [`calibench-vi/datasets`](https://huggingface.co/datasets/calibench-vi/datasets):
  the VI-Rig sets, `looper-insight9` and `gilabs-examples`, like the converted
  sets before. Access stays gated.
- **Before:** the VI-Rig sets were CC BY-NC 4.0 from 2026-09-11, the Looper and
  GiLabs sets from 2026-11-03. A copy downloaded then may now be used under
  CC BY 4.0 as well.
- **Unchanged:** device recordings in
  [`calibench-vi/community`](https://huggingface.co/datasets/calibench-vi/community)
  keep each folder's licence, CC BY-NC 4.0 unless the folder says otherwise. See
  [License](/about/license/#datasets).
